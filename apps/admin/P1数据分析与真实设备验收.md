# P1 数据分析与真实设备验收

## 数据分析接口

Admin 真实模式下，数据分析页面调用 `/api/v1/admin/report/operations`。运行时或终端接入后，可通过 `/api/v1/admin/report/events` 写入标准事件：

```json
{
  "eventType": "interaction",
  "exhibitionId": "exhibition-1",
  "terminalId": "terminal-a",
  "scene": "qa",
  "question": "机器人如何巡检？",
  "durationMs": 1200,
  "hit": true,
  "strongQaHit": false,
  "ragHit": true,
  "provider": "edge",
  "model": "edge"
}
```

支持的聚合接口：

- `/api/v1/admin/report/interaction`：交互量、平均响应耗时、场景/终端/小时分组。
- `/api/v1/admin/report/hotspot`：问题、展品、展商热点排行。
- `/api/v1/admin/report/hit`：命中、未命中、强控 QA、RAG 命中率。
- `/api/v1/admin/report/lead`：线索数量、转化数量和转化率。
- `/api/v1/admin/report/resource`：Provider/模型调用量和耗时。
- `/api/v1/admin/report/export?format=csv`：导出原始事件 CSV。

事件保存于 `OPENTALKING_ADMIN_DATA_DIR`（默认 `./data/admin`）下的 `report_events.json`，最多保留最近 10,000 条；正式部署时应由业务数据服务替换该文件存储。

## 真实设备验收顺序

1. 在 `humantalk` 环境启动 Redis 和 API，确认 `/healthz` 返回 `{"status":"ok"}`。
2. 使用真实浏览器打开 Web，允许麦克风权限，确认 WebRTC 视频轨、SSE 会话事件和连续监听均可恢复。
3. 使用真实 Admin 登录，确认 `/system/ops` 能显示 Redis 队列、STT/TTS provider 状态和主机资源。
4. 在 Admin 上传一份不超过 20 MB 的 GIF，检查预览、场景绑定、刷新后仍存在；删除被绑定 GIF 时应得到冲突提示。
5. 在 Admin 录入音色配置和待机内容，刷新页面后确认配置仍可读取；使用真实 `/tts/preview` 验证音色。
6. 在 Web 连续说三轮话，检查：识别文本不重复播报、播报中可打断、静音后监听自动恢复、关闭会话后麦克风轨道释放。
7. 记录设备型号、浏览器版本、网络环境、会话 ID、Trace ID、失败时间和截图/录屏，作为验收证据。

## 判定标准

- P0：WebRTC、SSE、语音输入、连续监听和播报中抢断无阻塞性故障。
- P0：Admin 资产上传/预览/绑定/删除和运行时健康检查不依赖 localStorage Mock。
- P1：报表页面展示真实事件；无事件时显示“暂无真实事件数据”，不得显示演示统计。
- P1：Redis 不可用、TTS/STT 未配置、麦克风权限拒绝时，页面给出可定位的错误状态。
