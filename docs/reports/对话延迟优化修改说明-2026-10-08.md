# 对话延迟优化修改说明

后续进展：按用户要求已上线服务器并完成8轮复测，另修复导航配置缺失导致关闭流式识别的问题。最新运行状态和数据见[上线复测报告](计算机大会服务器上线复测-2026-10-08.md)。以下记录本地修改阶段的状态。

日期：2026-10-08（香港时间）。依据“计算机大会”8轮真实前端测试及服务器日志完成本地修改。本轮没有部署、重启服务器或修改生产展会资料，因此暂时没有优化后的线上耗时数据。

## 1. 复用本轮知识库检索结果

`build_agent_context` 接收已经完成的 `knowledge_context`。有上下文时跳过知识库查询，仍读取用户长期记忆。检索未命中的提示也视为已完成检索，避免再查同样的三个知识库。QuickTalk/FlashTalk 合成路径和通用 SessionRunner 均接入；上下文加载失败时保留上游提供的资料。

## 2. 大模型调用和首段提前切分

数字人会话复用 HTTP 连接，结束会话时关闭连接池；运行时更新模型配置保留连接池，后续请求使用更新后的地址、密钥和模型。

在实际运行的 synthesis_runner 中启用首段切分：默认最少8字、20字目标上限，优先在逗号、分号等位置输出。超过目标长度或等待600毫秒后，在中文字符之间或单词间空白处切分。只对第一个片段应用；其余部分仍按完整句子处理。长度是安全边界上的目标值，不是对所有语言强制截断。等待阈值在新文本到达时检查，不额外轮询模型。

```dotenv
OPENTALKING_FLASHTALK_FIRST_SEGMENT_MIN_CHARS=8
OPENTALKING_FLASHTALK_FIRST_SEGMENT_MAX_CHARS=20
OPENTALKING_FLASHTALK_FIRST_SEGMENT_WAIT_MS=600
```

设置 `MAX_CHARS=0` 可恢复等待完整首句。知识资料提示同时要求先用简短首句回答，再按需补充。

增加 `OPENTALKING_LLM_EXTRA_BODY` JSON 配置，可传入提供商支持的生成选项。模型、消息和流式开关由客户端控制，不能被此配置覆盖。默认空配置，没有擅自更换模型或关闭思考：具体选项需按当前模型支持情况配置，并通过线上首 token 记录比较效果。HTTP连接复用和短首句不能保证消除上游模型的排队或计算耗时。

## 3. 标准问答直接播报

沿用展会后台的已发布问答，地点、时间等口语变体先归一再匹配。例如“在哪里举办”“举办地点”“会场地址”可以命中同一条问答，命中后直接合成，绕过检索和大模型。没有将检索片段自动当作标准答案，也没有编造或写入大会地点。

保持展会隔离、发布状态和每次读取最新记录；不同年份、往届限定、复合意图不会误用当前单项问答。若生产后台没有对应的已发布问答，仍会走检索和大模型，需要维护正式答案后才能使用直读路径。

## 4. 语音结束检测

默认静音等待从800毫秒改为600毫秒，保留原有开始说话阈值、攻击帧数、最短语段和抢话保护。空环境变量采用默认值，避免被误解析为0。慢速说话或噪声较高场景可通过构建时 `VITE_VOICE_SILENCE_MS=800` 恢复原值；真实嘈杂会场和自然停顿仍需现场验证。

## 5. 分段日志

- `QA match timing`：标准问答匹配耗时、是否命中、展会/turn/trace。
- `QA retrieval timing`：知识库检索耗时、结果数量。
- `Agent context timing`：是否复用知识上下文、上下文/记忆加载、说话锁等待。
- `LLM stream request / response headers / first content`：模型、消息及文本长度、连接复用、响应头和首正文耗时。
- `First TTS segment`：首段字数和送入合成队列的时间。

修正已有说话计时的起点：首段音频/媒体累计时间从取得说话锁后开始，包含准备与记忆、上下文阶段；排队到进入 speak 的时间使用实际进入时间。新旧日志的累计值不能直接当作同一起点比较，仍应以前端“语音结束到实际出声”为最终指标。

## 上线复测要求
