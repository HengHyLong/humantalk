# 中国计算机大会前端分段耗时测试

测试日期：2026-10-08，Asia/Hong_Kong（UTC+08:00）。

## 测试结果

已在 https://ai.oaii.cn:5173/ 的真实前端选择“中国计算机大会”，成功建立 QuickTalk / WebRTC 会话，完成 4 轮语音问答、2 轮文字问答、2 轮直接播报对照。测试问题为“计算机大会在哪里举办？”。线上展会实际绑定小米 MIMO `mimo-v2.5-asr`、Edge `zh-CN-XiaoxiaoNeural` 和 QuickTalk；本次链路未使用讯飞。

最明确的结论是：当前主要延迟在大模型首 token。SSH 日志中普通问答首 token 等待为 2.757～8.416 秒。绕过知识检索和 LLM 后，直接播报在 2.17～2.45 秒出声；普通问答提交后需 6.82～13.25 秒出声。识别请求本身为 0.89～1.84 秒，不能解释全部等待。

## 测量方式和边界

经用户明确授权，使用 Playwright 启动独立的无头 Edge 测试浏览器。真实加载线上页面和服务，未模拟后端问答、STT、TTS、QuickTalk 或 WebRTC 返回。麦克风输入为合成的中文 WAV 语音，通过浏览器测试音频设备进入页面正常录音/VAD链路，未使用用户真实麦克风。测试音频包含 5 秒前置静音、2.592 秒语音和 60 秒后置静音；长监听首次运行期间音频循环形成 3 轮语音测试，随后停止监听。最后另启动一轮监听并增加信号探针。

记录浏览器网络请求/响应、SSE `speech.started`、`subtitle.chunk`、`speech.media_started`、`speech.ended`。通过 WebAudio 对实际接收的远端音轨检测 RMS，首次超过 0.002 的时间记为出声时间。最后一轮对输入音轨同步检测 RMS，最后一次低于 0.014 的时间记为话音结束。信号采样间隔约 20 毫秒；结果包含本机测试浏览器、网络和音频缓冲的影响。

`speech.started` 仅表示进入任务，`speech.media_started` 仅表示媒体启动，均不等于用户已经听到声音。测试以远端音轨信号作为最终出声依据。无头浏览器没有真实扬声器声学测量，不包含操作系统输出设备额外延迟。

## 可以优先改进的地方

1. **优先缩短 LLM 首 token。** 服务端实测 2.757～8.416 秒，这是主要波动来源。应核对线上模型、上游排队与路由、提示词和重复上下文长度；若模型提供思考模式，检查是否有不必要的等待。更换模型或上游前，用相同问题比较首 token，不能仅依据支持流式判断速度。

2. **避免重复知识检索。** 问答接口已经返回 `match_type=rag`、知识来源和用于回答的上下文；本地代码的 `FlashTalkRunner.speak()` 在收到 `knowledge_context` 后，仍先调用 `_build_agent_context(text)`，然后把两份上下文合并。会话的知识开关开启并绑定三个库，该路径具备重复检索条件。建议当已有本轮检索上下文时复用它，同时保留必要的记忆处理。服务器日志已确认同一轮对三个知识库各检索两遍，重复检索净耗时尚无独立埋点。

3. **在实际使用的流水线里提前提交首段。** `synthesis_runner.py` 的 LLM feeder 使用 `SentenceSplitter.feed()`，等待硬标点才进入 TTS。实测前五轮普通问答的第一字幕为 38～81 字的完整长句。`SessionRunner` 已有的首段软标点/长度切分逻辑并不覆盖所有 `FlashTalkRunner` 路径。建议把首段 6～20 字、软标点或受控时间阈值提交策略应用到实际 QuickTalk 流水线，保留后续句子的自然切分。不能只调整另一个 runner 的参数就宣称线上优化生效。

4. **把常见事实问答配置为标准问答直接播报。** 本题检索结果已包含标准答案，但每轮仍 `speak_mode=agent`，导致反复生成且第一句话不稳定。对地点、时间、主办方等明确问题，优先匹配经维护的标准问答，绕过 LLM，或缓存完整回答/语音。需要保留展会和知识版本隔离、失效更新及语义匹配约束。直接播报对照显示该路线具有明显改善潜力，但并未更改线上业务配置。

5. **补齐还缺少的后端埋点。** 建议记录 `agent_context_done`、`llm_first_token`、`first_sentence_committed`、`tts_first_pcm`、`first_inference_return`、`first_av_queued`，均关联 session_id/turn_id/trace_id。SSH 日志已确认 LLM 首 token 为最大延迟来源；仍需补充上下文准备和首句提交时间，以量出重复检索与等完整句子的独立开销。

6. **最后再缩短 VAD。** 实测静音分句 0.823 秒符合默认 800 毫秒；在现场噪声测试稳定后可尝试 400～600 毫秒，预计只减少数百毫秒。小米当前录完后提交的识别方式可另评估真正流式替换，但本题 ASR 不是最大瓶颈。修改讯飞不会自动改变当前展会的小米绑定。
