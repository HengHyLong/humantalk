# V1.5 展会互动问答

## 运行链路

`POST /exhibitions/{exhibition_id}/qa/query` 是 Web 的统一问答入口。服务端按以下顺序处理：

1. 输入安全检查；
2. 仅匹配 `status=published` 的强控 QA；
3. 调用当前展会对应的 Dify 数据集，未配置 Dify 时兼容本地 OpenTalking 知识库；
4. 有检索片段时，把可信上下文直接送入当前 session 的 Agent/LLM/TTS/数字人管线；
5. 模糊且缺少对象的问题先返回澄清问题；
6. 明确问题最终无结果时累计到 `miss_pool`；
7. 检索请求异常返回 `retrieval_error`，不计为业务未命中。

强控 QA、澄清、兜底和安全拦截使用 `direct` 播报；RAG 结果由 Agent 基于检索片段生成最终答案。

## 请求

```json
{
  "session_id": "sess_xxx",
  "turn_id": "turn_xxx",
  "question": "服务中心在哪里？",
  "locale": "zh-CN",
  "voice": "zh-CN-XiaoxiaoNeural",
  "tts_provider": "edge"
}
```

响应中的 `match_type` 为：

- `official_qa`：已发布官方 QA；
- `rag`：Dify 或本地知识库命中，Agent 正在生成；
- `clarification`：需要用户补充对象；
- `fallback`：确认未命中，已进入未命中池；
- `retrieval_error`：知识服务故障，不进入未命中池；
- `blocked`：输入安全规则拦截。

响应同时返回 `turn_id`、`trace_id`、命中分数和来源摘要。Dify API Key 只保存在服务端。

## 配置

```dotenv
OPENTALKING_DIFY_BASE_URL=https://api.dify.ai/v1
OPENTALKING_DIFY_API_KEY=<server-side-key>
OPENTALKING_DIFY_DEFAULT_DATASET_ID=<dataset-uuid>
OPENTALKING_DIFY_DATASET_MAP={"expo-2026":"dataset-uuid"}
OPENTALKING_DIFY_TIMEOUT_SEC=12
OPENTALKING_QA_FUZZY_THRESHOLD=0.74
OPENTALKING_QA_RETRIEVAL_TOP_K=3
OPENTALKING_QA_RETRIEVAL_SCORE_THRESHOLD=0.45
OPENTALKING_QA_HUMAN_CHANNEL=请前往现场服务台或咨询工作人员获取帮助。
```

展会记录或知识库记录也可以通过 `difyDatasetId`/`datasetId` 提供数据集绑定。优先级为：

1. `OPENTALKING_DIFY_DATASET_MAP`；
2. 展会记录；
3. 展会知识库记录；
4. `OPENTALKING_DIFY_DEFAULT_DATASET_ID`。

## 验收用例

1. 原问题和同义改写命中同一条已发布 QA；
2. 草稿、待审和已回滚 QA 不生效；
3. QA 未命中后调用 Dify，来源与分数在 Web 可见；
4. “那个在哪”先追问，不写未命中池；
5. 明确问题无检索结果时，相同问题累计次数；
6. Dify 超时、401、5xx 不增加未命中次数；
7. 提示词注入和索要密钥被拦截；
8. 文字、短语音、流式语音均进入同一问答入口；
9. 新问题自动打断上一轮播报；
10. LLM/TTS/数字人不可用时保留文字、错误码和 Trace 诊断信息。
